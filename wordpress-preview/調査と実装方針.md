## 採用する実装

Reactの画面構成と配色を基に、WordPressのPHPテンプレートとして再構成。ReactやNode.jsをXサーバーで実行する必要はありません。

| 部分 | 実装 |
|---|---|
| 対象 | Cocoon Child内の追加型固定ページテンプレート |
| 適用範囲 | 「ハナのトップページ（テスト用）」を選んだ固定ページのみ |
| タイトル | 専用カスタマイザー。WordPress全体のサイト名設定は自動変更しない |
| ヒーロー | 左にHTML文字、右に画像。スマホは文字の下に画像 |
| メイン画像 | メディアライブラリの添付ID。画像全体を表示、切り抜きなし、文字重ねなし |
| カテゴリ | 指定順に6つのカテゴリ入口。リンク先は既存カテゴリIDから管理者が選択 |
| 投稿表示 | 公開済み・パスワードなしの通常投稿を新しい順に6件。ページ送りあり |
| 投稿リンク | WordPressの実際のパーマリンク。既存記事は通常のCocoon表示 |
| 記事画像 | アイキャッチ画像。未設定時は対応するカテゴリ画像。カテゴリ未対応時はかごの水彩風画像 |
| ROOM | 管理画面でURL入力。空欄なら無効リンクを作らず準備中表示 |
| ブログ紹介 | 固定ページ本文を表示。空なら初期紹介文 |
| 外部依存 | 外部フォント、CDN、JavaScriptフレームワーク、外部APIなし |

「おいしいもの・暮らしの道具・ハナとの日常・おしゃれ・お出かけ・美容と健康」は、この順番の6つのカテゴリ入口として配置。新着記事、ROOM、ブログ紹介が続きます。

既存表示名の「グルメ・暮らし・ペット・ファッション・旅行・美容」は対応候補にすぎません。実際のWordPressカテゴリを未調査のため、自動でカテゴリを追加・削除・改名しません。未設定は準備中と表示します。

## Cocoonとの境界

この専用テンプレートは独自のheader/main/footerを出力し、Cocoonの通常のサイドバー、パンくず、固定ページタイトル、本文広告枠を呼び出しません。余白とヒーローを安定させるための設計です。

`wp_head()`、`wp_body_open()`、`wp_footer()`、`body_class()`、WordPressの標準投稿APIは維持します。SEO・アクセス解析・管理バー等のフックが動く構成ですが、実際のCocoonバージョン、スキン、プラグインによるCSSやスクリプトとの組み合わせは別途テストが必要です。フック経由の自動広告があれば表示される可能性があります。

このテンプレートでのみ専用CSSを読み込み、`.hh-site`を中心にスタイルを限定。`front-page.php`、既存`style.css`、既存`functions.php`の丸ごと置換は行いません。

## 安全性・データの扱い

- 自動の投稿作成、カテゴリ変更、ホームページ切り替え、オプション更新、SQL、ファイル削除処理なし。
- カスタマイザーで保存した専用設定だけが通常のWordPressテーマ設定として保存される。設定保存は導入先でユーザーが行う。
- 出力文字とURLを適切にエスケープ。画像は画像添付ID、カテゴリは存在するカテゴリIDへ検証。
- 公開投稿のみを一覧化し、パスワード付き投稿は除外。固定ページ自体のパスワード保護も尊重する。
- 独自クエリ終了後は`wp_reset_postdata()`を実行。
- 未知の本番設定を仮定しない。旧GitHubのROOM URLは自動採用せず、導入者が所有先を確認して入力する。

## 素材

1.2ではカテゴリと記事見本の素材を、AI生成の水彩風PNG画像（1536×1024、6つのモチーフ）へ変更しました。旧版の角ばったSVG素材はパッケージから削除。元画像を加工せず、CSSで6つの領域を表示します。管理画面から各カテゴリの画像を個別に指定でき、メディアIDを検証します。アイキャッチ未設定記事にもカテゴリ画像を利用します。人物やハナ本人の画像は生成しておらず、メイン画像は従来どおり後から指定します。以前の「私とハナ」の画像自体は未参照です。
