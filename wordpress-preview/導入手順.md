# 初心者向け：テスト設置から導入まで

**いま行うのは別のテスト環境での確認です。本番にはまだ設置しません。**

このパッケージはCocoon Childにファイルを追加するものです。WordPress本体、Cocoon親テーマ、既存の子テーマ一式を置き換えるものではありません。

## 1. まずパソコンでデザインを見る

ダウンロードしたZIPを解凍し、`preview`フォルダの`index.html`をダブルクリックします。PC画面と、ブラウザを細くしたときの見え方を確認してください。`desktop.png`と`mobile.png`は画面見本です。

この見本には本番の記事は含まれていません。カードを押すとサンプルの説明に移動します。WordPress版では実際の投稿へ移動します。メイン画像は選択された「私とハナ」のイラストを表示しています。

## 2. 本番と別のテスト用WordPressを用意する

推奨は、パソコン上のLocalなどで新規WordPressを作り、CocoonとCocoon Childを入れる方法です。本番のデータをコピーする必要はありません。新しく作ったテスト記事で確認できます。

Xサーバーで試す場合は、テスト専用サブドメインと新しい設置先・新しいデータベースを使い、WordPressを新規設置してください。本番ドメイン`60daihanato.com`の既存設置先や既存データベースは選ばないでください。設置場所が判別できない場合は、作業を進めずXサーバーのサポートへ確認してください。

テスト用サイトにはサーバー側のアクセス制限（Basic認証など）をかけ、WordPressの「設定 → 表示設定」で検索エンジンによるインデックスを抑制します。検索エンジンのチェックだけでは非公開にはなりません。本番DBへの接続情報をテスト環境へ入れないでください。

## 3. テスト環境でCocoon Childを有効にする

テスト用WordPressの「外観 → テーマ」で、Cocoon親テーマがインストール済みであることを確認し、「Cocoon Child」を有効にします。公式配布元のテーマを使用してください。

ファイル操作の前に、このテスト用子テーマの`functions.php`をパソコンへ保存しておきます。

## 4. ファイルを2か所追加する

テスト環境のファイルマネージャーやSFTPを使って、**有効なCocoon Childのフォルダ**を開きます。通常は次のような場所ですが、フォルダ名は環境により異なります。

```
テストWordPressの設置先/wp-content/themes/cocoon-child-master/
```

パッケージの`cocoon-child-additions`の中から、次の2つを、その子テーマフォルダへ追加します。

```
cocoon-child-master/
├── functions.php          ← 既存ファイル。削除・丸ごと置換しない
├── style.css              ← 既存のまま
├── page-hana-home.php      ← 今回追加
└── hana-home/              ← 今回フォルダごと追加
    ├── setup.php
    └── assets/
        ├── home.css
        ├── watercolor-sheet.png
        └── hana-hero.jpg
```

同名の`page-hana-home.php`や`hana-home`が既に存在する場合は、上書きせず内容を確認してください。`preview`、手順書、ZIPそのものはサーバーにアップロードしません。

続いて、保存しておいた**テスト用の既存`functions.php`**をテキストエディターで開き、PHPコード内の末尾へ次の1行だけ追加します。

```php
require_once get_stylesheet_directory() . '/hana-home/setup.php';
```

新しい`<?php`は追加しません。末尾に`?>`がある場合は、その直前へ追加します。既存のPHPコードを書き換えず、同じ行を重複して追加しないでください。編集後のファイルを同じテスト用フォルダへ戻します。WordPressのテーマファイルエディターで直接編集するより、手元で編集し、戻せるコピーを残す方法を推奨します。

## 5. テスト用の固定ページを作る

1. **テスト用管理画面**で「固定ページ → 新規固定ページを追加」を開きます。
2. 管理用タイトルを「トップページ・テスト」にします。
3. ページ設定の「テンプレート」で **ハナのトップページ（テスト用）** を選びます。クラシックエディターでは「ページ属性」にあります。
4. 本文は空欄で構いません。本文を入力すると、下部の「このブログについて」に表示されます。ここにトップページ全体のHTMLを貼る必要はありません。
5. 最初は下書きで保存し、プレビューで確認します。ページ送りやカスタマイザーの確認は、テスト環境でのみ「非公開」にして保存したページ、またはBasic認証で保護したテストサイトの公開ページで行うと確認しやすくなります。

まだ「設定 → 表示設定」のホームページは変更しません。専用固定ページのURLだけでデザインを確認できます。

## 6. 管理画面で画像・カテゴリ・ROOMを設定する

「外観 → カスタマイズ → **ハナのトップページ**」を開きます。右側の見本に通常のトップページが出ている場合は、テスト用固定ページをブラウザで開き、上部の管理バーから「カスタマイズ」を選びます。

### メイン画像

1.3では選択済みの「私とハナ」を `hana-home/assets/hana-hero.jpg` に同梱し、画像設定が空欄なら自動表示します。そのまま使う場合、メディアへの再アップロードは不要です。既に別の画像を選択している場合は、その画像が優先されます。同梱画像へ戻すにはカスタマイザーのメイン画像の選択を解除してください。

別の画像へ差し替えるときは「文字なしの『私とハナ』イラスト」から画像を選び、JPG・PNG・WebPなどをメディアにアップロードしてください。横長・幅1200〜1600px程度を目安に、容量が大きすぎない画像を用意します。SVGはメイン画像としてアップロードする必要はありません。

メディアライブラリの「代替テキスト」へ、実際の画像に合う短い説明を入力します（例：「窓辺でハナとくつろぐ私」）。画像に合わせて内容を変えてください。

タイトルとサブタイトルは別欄のテキストです。画像上へ重なりません。画像全体を表示するため、画像の縦横比によって余白や高さが変わります。

### 6つのカテゴリ

各「リンク先」で既存カテゴリを選びます。表示名とWordPressカテゴリ名は同じでなくても構いません。

| トップページの表示名 | 対応するカテゴリの例 |
|---|---|
| おいしいもの | グルメ |
| 暮らしの道具 | 暮らし |
| ハナとの日常 | ペット |
| おしゃれ | ファッション |
| お出かけ | 旅行 |
| 美容と健康 | 美容 |

これは候補です。実際のカテゴリを確認して選んでください。カテゴリを削除・改名する必要はありません。未設定の場合は「ただいま準備中」と表示され、リンクは作りません。設定済みでも記事0件なら、WordPressのカテゴリ一覧に記事なしの状態が表示されます。

### カテゴリ画像の差し替え（水彩風イラスト版 1.2）

同じ設定欄に「おいしいもの のイラスト」など6つの画像選択項目があります。それぞれ「画像を選択」でJPG・PNG・WebPをアップロードまたは選択できます。正方形・600px程度を目安に、絵の周囲に少し余白のある画像を使うと揃います。画像は全体を表示します。

未設定、または選択した画像が削除された場合は、同梱のAI生成水彩風イラストを表示します。6種類は1枚のPNG画像シートをCSSで表示範囲ごとに使い分けています。差し替えるときはシートを加工する必要はなく、各カテゴリに1枚ずつ画像を選ぶだけです。

記事の画像は「投稿」のアイキャッチ画像で変更します。アイキャッチを設定済みの記事を今回のイラストで置き換えることはありません。アイキャッチのない記事は対応するカテゴリ画像、カテゴリ未対応の記事はかごのイラストを表示します。複数カテゴリに該当する場合はトップのカテゴリ順で最初の一致を使います。親カテゴリの子だけに属する記事は、必要に応じてその子カテゴリをリンク先に指定してください。

既にテスト用の旧版を設置済みなら、まずそのテスト用子テーマを保存してから、`page-hana-home.php`、`hana-home/setup.php`、`hana-home/assets/home.css`を新版に置き換え、`watercolor-sheet.png`を追加します。既に追記済みのfunctions.phpの1行を重複追加する必要はありません。キャッシュを消し、6カテゴリ画像と投稿画像の優先順位を確認してください。旧SVGファイルが残っていても新版では参照しません。

### 楽天ROOM

ご自身のROOMを開き、そのURLをコピーして貼り付けます。旧GitHubコードの登録先は`https://room.rakuten.co.jp/room_c836dc669f/items`ですが、ご自身の案内先であることを確認したうえで入力してください。初期状態では空欄です。リンク先で紹介報酬が発生する可能性を示す文言を含めています。

変更をテスト環境で保存します。カスタマイザーの保存ボタンはWordPressの版により「公開」と表示されます。**テスト環境のURLであることを確認してから**保存してください。

## 7. 記事を追加する

通常どおり「投稿 → 新規投稿を追加」で記事を書き、カテゴリとアイキャッチ画像を設定します。「公開」した通常投稿が新しい順にトップページへ出ます。

- 下書き、予約、非公開、パスワード付き投稿は新着一覧に出ません。
- 画像未設定の投稿にはカテゴリの水彩風イラストが表示されます。カテゴリが未対応の場合はかごのイラストです。
- 最新6件を表示し、7件以上あれば「以前の記事」から続きを読めます。
- 記事カードを押すと通常のCocoonの記事ページへ移動します。
- 紹介文を変える場合は、テスト用固定ページの本文を編集します。紹介文を空にすると初期の文章に戻ります。

## 8. 完成確認のチェックリスト

- [ ] 320px・390px程度のスマホ幅で横にスクロールせず読める
- [ ] 文字なしイラストが切れず、タイトルが画像に重ならない
- [ ] 6カテゴリの順番とリンク先が合っている
- [ ] 7件以上のテスト投稿でページ送りが使える
- [ ] 下書き・非公開・予約・パスワード付き投稿が新着に出ない
- [ ] 画像なし・長いタイトルでも表示できる
- [ ] ROOMのリンク先が自分のページで、新しいタブで開く
- [ ] 固定ページ本文を変更すると「このブログについて」が変わる
- [ ] 既存形式の記事・固定ページの見た目と動作が変わらない
- [ ] 使用予定のCocoonスキンやプラグインとの組み合わせで問題がない
- [ ] テストサイトの公開設定・パスワード保護に問題がない

本パッケージは標準APIで実装していますが、お使いのWordPress/Cocoon/PHP/プラグインの組み合わせでの検証は、このテスト環境で完了させてください。

## 9. 確認後、将来本番へ導入するときだけ

**この制作作業では実施していません。以下は、デザイン承認後にご自身で行う手順です。**

1. 本番のファイル・データベースの復元可能なバックアップを用意します。「設定 → 表示設定」の現在の内容と、有効テーマ名を控えます。
2. 本番がCocoon Childであることを確認します。別テーマなら、このまま切り替えず、移行の影響を別途確認します。
3. 本番子テーマの`functions.php`を別途保存し、手順4と同じ2つのパスと1行を追加します。テスト用のfunctions.php全体を本番へコピーしません。
4. 新しい固定ページを作り、テンプレートを選び、最初は下書きで確認します。既存の固定ページを消したり上書きしたりしません。
5. 同梱メイン画像を使う場合はメディアへのアップロードは不要です。カスタマイザーで別画像に差し替える場合は本番のメディアにアップロードし直します。カテゴリ・ROOMも本番で選び直します。画像IDとカテゴリIDは環境ごとに異なるため、テスト環境のDBや設定値を丸ごとコピーしません。
6. 最終確認後、その新しい固定ページを公開します。「設定 → 表示設定 → ホームページの表示 → 固定ページ」で、新しいページをホームページとして選びます。既存の「投稿ページ」がある場合はその指定を維持し、同じページを両方に指定しません。
7. 必要に応じてキャッシュを削除し、ログアウト状態のPC・スマホで確認します。既存記事URLが変わっていないことも確認します。

サイト名の全体設定は自動変更しません。このデザインのタイトルは専用カスタマイザーで変更できます。検索結果のサイト名や既存ページのヘッダー名も変更したい場合は、それは別途WordPress全体の設定として検討します。

## 10. 元に戻す方法・困ったとき

**以前のトップページへ戻したい：** 「設定 → 表示設定」を控えておいた内容へ戻します。新しい固定ページは下書きに戻せます。記事やカテゴリの削除は不要です。

**専用テンプレートを使わない：** 対象の固定ページでテンプレートを「デフォルト」に戻します。

**1行追記後に白い画面・重大なエラー：** ファイルマネージャーやSFTPで、バックアップした元の`functions.php`を戻します。続けて管理画面に入れることを確認します。既存ファイルの他の部分を削除しないでください。

**テンプレートが一覧に出ない：** 有効なCocoon Childの直下に`page-hana-home.php`があるか、二重フォルダになっていないか確認します。固定ページを開き直してください。

**設定項目が出ない：** `functions.php`への1行と、`hana-home/setup.php`の置き場所を確認します。

**見た目が古い・崩れる：** テスト環境でキャッシュを削除し、スキンや追加CSSの影響を切り分けます。本番のプラグインや設定を試しに削除しないでください。

追加ファイルを取り除く必要がある場合は、まずこのテンプレートを使うページをデフォルトへ戻し、functions.phpの追加した1行を外してから、今回追加したファイルだけを取り除きます。設定が残っていても既存記事に影響しないため、データベースを直接操作して削除する必要はありません。

## 1.2から1.3へテスト環境を更新する場合

テスト用子テーマを保存してから、`page-hana-home.php`、`hana-home/setup.php`、`hana-home/assets/home.css`を新版に置き換え、`hana-home/assets/hana-hero.jpg`を追加します。functions.phpの1行は追記済みなら変更不要です。キャッシュを削除して見た目を確認してください。既存のカスタマイザーのメイン画像を設定している場合は、その選択が優先されるため、同梱画像へ戻すときだけ選択を解除します。
